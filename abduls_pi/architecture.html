Design Engineering Pillars

01

Perceived Speed & Response

Using lightweight models and minimal system prompt weight ensures sub-second time-to-first-token. Following Emil's rule that speed dictates perceived quality.

Target: < 300ms model TTFT
02

Progressive Disclosure

Instead of cluttering the prompt with entire skill manuals, the agent inspects a lightweight overview and lazy-loads instructions via load_skill only when needed.

Pattern: On-demand context hydration
03

Responsibility & Safety

Filesystem and bash tools are rigidly sandboxed to project root. Mandatory citations (city names, rate dates) ensure factual integrity with zero guessing.

Pattern: Absolute path boundary checks

System Craft Audit

Before / Standard Our Architecture After Why (Design Engineering Rationale)
Monolithic system prompt with all skill docs Lazy-loaded `skill_overview()` + `load_skill` Keeps context clean and saves token budget for complex reasoning tasks.
Relative imports (`from .tools import ...`) Absolute package imports (`abduls_pi.tools`) Prevents LangGraph CLI server load errors and circular dependency traps.
Bare python execution (`python3`) `uv run` or `.venv/bin/python` Guarantees dependency isolation against system python runtimes.
